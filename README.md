# «Как рождается алгебра» — сайт курса «Мысли как математик»

Этап 1 плана: посадочная страница и двухшаговая заявка родителя с админкой.
Основание — исходные документы в [`docs/requirements/`](docs/requirements/): ТЗ MVP 1.1, прототип пути пользователя, макеты экранов (PDF) и план реализации.

## Что входит в этап 1

| Часть | Что сделано |
|---|---|
| Лендинг `/` | Все 13 блоков ТЗ §5: шапка, первый экран, узнавание, методика (6 шагов), уровни с ценами и статусом набора, формат, преподаватель, «Персональный маршрут», «Для учителей» (выключен до этапа 5), как попасть в группу, доверие, FAQ, финальный призыв с короткой формой. Закреплённая кнопка на телефоне после первого экрана |
| Заявка `/apply` → `/apply/details` → `/success` | Шаг 1 (имя, телефон/Telegram, email, класс, согласие) сразу создаёт заявку. Шаг 2 — цель, трудности, расписание, часовой пояс, интерес к «Персональному маршруту», лист ожидания. Возврат позже — поля подставлены. Повторная отправка не создаёт дубль |
| Админка `/admin` | На русском. Заявки (статусы, заметки, лист ожидания, UTM, согласия), уровни и цены, тексты главной и формы, FAQ, отзывы (только с согласием), юр. документы, настройки, сотрудники с ролями |
| Доставка заявок | Уведомление преподавателю в Telegram и копия в CRM/таблицу через очередь с повторами. Если родитель оставил только контакт — напоминание через 30 минут |
| Аналитика | Яндекс Метрика (номер счётчика — в админке), события ТЗ §10 этого этапа, UTM сохраняются в заявке, баннер cookie |
| Качество | SEO (title/description, canonical, OG, sitemap, robots, JSON-LD Course/Person/FAQ), доступность (метки, фокус, ошибки у полей не только цветом), LCP ≈ 0,9 с в локальном мобильном замере |
| Поставка | Dockerfile, production-compose с Caddy (HTTPS), миграции, скрипты бэкапа/восстановления, CI |

Не входит (следующие этапы): тестирование учеников, предложение группы и оплата, возвраты, форма комьюнити учителей.

## Стек

Next.js 16 (App Router) · Payload CMS 3 (админка, данные, очередь задач) · PostgreSQL 17 · TypeScript · Zod (одни правила проверки формы на клиенте и сервере). Стили — обычный CSS без фреймворка, шрифт Golos Text (подключается при сборке, без запросов к Google в браузере).

## Локальный запуск

Нужны Node.js 20.9+ и Docker.

```bash
cp .env.example .env            # и задайте PAYLOAD_SECRET: openssl rand -hex 32
docker-compose up -d            # PostgreSQL на 127.0.0.1:5432
npm ci
npm run seed                    # стартовый контент из ТЗ (безопасно повторять)
npm run dev                     # http://localhost:3000, админка — /admin
```

При первом входе в `/admin` создаётся первый сотрудник — он автоматически становится администратором.

Доступ с других устройств в локальной сети: `npm run dev:lan`. В `.env` укажите `DEV_ORIGINS=<IP компьютера>` и `SITE_URL=http://<IP>:3000`. В разработке админка работает по относительным адресам, поэтому вход проходит и через `localhost`, и по IP. В production `serverURL` и проверка источника cookie (csrf) включены — сайт должен работать по HTTPS.

В разработке схема базы синхронизируется автоматически. После изменения коллекций создайте миграцию для production:

```bash
npm run payload migrate:create <название>
```

Production-сервер нельзя направлять на dev-базу: она создана без миграций, и Payload остановится с вопросом.

## Как устроена заявка

1. Шаг 1 отправляется на `POST /api/lead/step1`. Сервер проверяет поля, ловушку для ботов (скрытое поле и форма, отправленная быстрее 2 с) и ограничение частоты. Затем создаёт заявку со стадией «Только шаг 1», сохраняет версию согласия и UTM и ставит httpOnly-cookie со случайным токеном. В базе хранится только хеш токена; номер заявки наружу не отдаётся.
2. Повтор той же отправки (двойной клик, обрыв связи) распознаётся по ключу операции: заявка остаётся одна.
3. Шаг 2 (`POST /api/lead/step2`) находит заявку по cookie и дописывает цель и расписание. Заполненную заявку можно поправить в течение суток, после этого форма создаёт новую — например, на второго ребёнка.
4. Доставка идёт через очередь Payload (`payload-jobs`). Webhook уходит на шаге 1 и при заполнении, уведомление преподавателю — при заполнении. Для незавершённых заявок напоминание уходит через 30 минут, если шаг 2 так и не заполнен. При ошибке задача повторяется с нарастающей паузой (6 попыток), последняя ошибка видна в заявке.

## Переменные окружения

См. `.env.example`. Ключевые:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL`, `PAYLOAD_SECRET` | обязательные |
| `SITE_URL` | публичный адрес: canonical, sitemap, ссылки в уведомлениях. Читается при запуске, не при сборке |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления преподавателю. Бот должен быть добавлен в чат |
| `TELEGRAM_INCLUDE_CONTACTS` | `true` — класть контакты родителя в сообщение. По умолчанию только класс, цель и ссылка в админку (серверы Telegram вне РФ) |
| `LEADS_WEBHOOK_URL`, `LEADS_WEBHOOK_SECRET` | копия заявок в CRM/таблицу. Тело подписывается HMAC-SHA256 (`x-mkm-signature`), получатель обновляет запись по `lead_id` |

Номер счётчика Метрики, контакты, срок ответа и включение блоков задаются в админке («Настройки сайта»).

## Аналитика

События задаются в одном месте: `src/lib/analytics-events.ts`. В Метрике для них создаются цели типа «JavaScript-событие» с теми же идентификаторами.

| Событие | Когда | Параметры |
|---|---|---|
| `page_view` | открытие страницы | page, device, source |
| `cta_click` | клик по кнопке | location, cta_type, level |
| `form_step1_submit` | сервер сохранил шаг 1 | class, source, utm, location, level |
| `form_complete` | сервер сохранил шаг 2 | level, tariff, goal, schedule, personal_route, waitlist |
| `contact_click` | клик по Telegram | location |

Контакты, имена и свободный текст в аналитику не передаются.

## Деплой (VPS + Docker)

Персональные данные граждан РФ должны храниться на серверах в России (152-ФЗ): Selectel, Yandex Cloud, Timeweb и т.п.

```bash
# на сервере, в каталоге проекта
cd deploy
cp .env.production.example .env.production   # заполнить; пароль БД — без спецсимволов: openssl rand -hex 24
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

- Миграции применяются автоматически при старте приложения.
- Стартовый контент на сервере: проще всего заполнить через админку. Либо один раз выполнить `npm run seed` с `DATABASE_URL` этого сервера и `NODE_ENV=production`.
- HTTPS выдаёт и продлевает Caddy, нужна A-запись домена на сервер.
- Staging — тот же compose на отдельном сервере или в отдельном каталоге со своим `.env.production` и доменом.

Бэкап — `scripts/backup.sh` по cron (база + изображения, хранение 14 дней), восстановление — `scripts/restore.sh`. Копии желательно дополнительно уносить с сервера.

## Решения, принятые на этапе 1

- Контакт — на шаге 1, согласие — тоже на шаге 1: заявка сохраняется сразу после него (в PDF-макете было наоборот).
- Обязательны и телефон/Telegram, и email (решение владельца).
- Количество занятий и цены — по ТЗ (8 занятий / 13 000 и 16 000 ₽; олимпиадный — 12 занятий / 24 000 ₽), а не по PDF. Всё редактируется в админке.
- Ярлык «Новичок» не используется (ТЗ §5.3).
- Тексты, обещавшие тест на сайте, временно сформулированы без него; кнопка теста включается в настройках на этапе 2.
- `/offer` зарезервирован под юридическую оферту (этап 3), персональное предложение будет по `/proposal/:token`.
